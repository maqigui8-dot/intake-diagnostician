# P01
本项目面向成人肥胖诊前问诊。核心不是线上直接确诊，而是把患者的基础资料、主诉、风险和中医症状整理成医生可用的诊前资料。

# P02
系统的定位是“为诊中服务”。患者完成采集后，医生仍然要在诊中完成辨证、风险判断和治疗决策，系统只负责减少重复问诊与遗漏。

# P03
改造前主要有三类问题：固定问答无法承接自然表达；刷新后追问状态可能断开；按单一分数结束会让资料未齐时过早生成档案。

# P04
本轮改造明确了分工。规则计算 BMI、判断门槛和安全条件；AI 负责理解原话、组织追问、解释术语。AI 不直接诊断、开方或修改停止条件。

# P05
当前流程是：先收集基础资料，再接收开放描述，随后按缺失信息分层追问，最后汇总为诊前档案和检查候选。患者端不展示内部执行度。

# P06
进入成人肥胖流程前，系统会先校验年龄，并要求年龄、性别、身高和体重这四项基础资料齐全。BMI 和腰围等数值由服务端计算，减少模型推断的不确定性。

# P07
完整度不是固定轮次，而是四层门槛：基础资料、病因与风险、中医资料、安全信息。只有满足对应要求后，系统才生成正常完成的诊前档案。

# P08
什么时候问够，不由固定轮次决定。只有硬性前提齐全、当前场景的信息覆盖达到要求、没有待核实的关键风险或矛盾，并且对“不知道”或“拒答”完成一次合理澄清后，系统才结束追问并生成诊前档案；否则继续补最关键的缺失字段。

# P09
追问页改为聊天形式。每一次提问对应一个待补全的信息目标；患者不理解时会先解释；同一字段最多委婉重问一次。即使 AI 服务不可用，也会降级到固定问题继续采集。

# P10
系统输出分为两端：患者端使用易理解且安全的表达，显示诊前摘要和检查建议；医生端保留字段来源、完成情况和矛盾信息，方便诊中核对。

# P11
本周已完成从固定问答到对话式采集、四层完整度模型和双端结果分层。下一步会继续补充端到端测试、访问控制和文档收口。
