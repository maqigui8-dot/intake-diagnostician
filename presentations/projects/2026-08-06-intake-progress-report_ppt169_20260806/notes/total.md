# 01 封面

本次汇报介绍中医诊前问诊系统的阶段进展。本轮工作不是简单增加问卷题目，而是重新定义信息完整度，引入动态补问，并把分析结果收敛到信息完整度和检查建议两个方向。

# 02 组会反馈与目标调整

本轮首先调整了项目目标。过去更接近固定问卷，容易把题目答完等同于信息完整。现在改为结合十问歌框架和中医问诊经验判断缺口，最终形成后续诊中能够继续使用的信息档案，同时明确分析边界。

# 03 新的诊前问诊流程

新的流程以基础问诊为起点。完整度 Skill 负责识别缺失内容，系统选择一个优先级最高的问题进行动态补问，追问 Skill 负责生成自然、准确的表达。用户回答后再次评估，满足条件后形成档案和检查建议。

# 04 两个 Skill 如何分工

两个 Skill 的职责被明确拆开。第一个回答应该问什么，输出必问项、选问项和完整度状态；第二个回答应该怎么问，控制一次一问、通俗表达、避免诱导和不重复。这样便于规则独立维护，也减少模型职责混杂。

# 05 动态补问闭环

动态补问的核心是每轮只处理一个关键缺口。回答完成后系统重新评估，而不是一次生成大量追问。当前最多补问五轮，补问内容会回填到最终档案，既控制问诊长度，也保证信息能够逐步补齐。

# 06 智能分析内容收敛

智能分析不再提供辨证、诊断或处方方向，只保留信息完整度、安全提示和推荐检查项目。检查建议使用结构化字段，包括名称、类型、科室、临床意义、优先级和注意事项，参考体检项目资料，但不提供价格和医疗结论。

# 07 工程实现与稳定性

工程上将分析 Agent 与普通问诊流程分离，把两个 Skill 内容合并到一次模型调用中，并放入后台线程执行。系统设置四十五秒超时和重试入口，结构化保存基础回答、补问和分析结果。目前后端二十二项测试通过，前端构建和接口健康检查也已通过。

# 08 当前结论与下一步

目前核心方向已经落地：完整度规则重构、两个 Skill 拆分、动态补问闭环、分析范围收敛、检查建议结构化和稳定性优化。下一步重点是继续细化字段与规则，引入临床审核，并通过更多真实场景验证系统表现。
