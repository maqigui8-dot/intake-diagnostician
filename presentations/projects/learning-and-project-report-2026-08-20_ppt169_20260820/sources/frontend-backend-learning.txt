# **一.前后端学习**

## 1.基本要求

1.1 前端学习：
⚫ 前端基础：了解前端三件套，HTML/CSS/JavaScript，学习使用
Vue 框架，掌握Git 基本使用，npm/pnpm/yarn 简单使用
⚫ 前端进阶：TypeScript（类型约束、泛型）的使用，主流框架
（Vue3 + Vite）搭配 TypeScript 使用 Vue | Vue.js

1.2 后端学习：
⚫ 后端基础：以 Java（Spring Boot） 构建核心业务服务；掌握
MySQL 或 PostgreSQL 的数据库核心操作（熟练 CRUD）；使用
Python（FastAPI） 独立封装算法接口，打通 AI 算力与业务前
端的链路。
➢ 开发工具：Trae编程工具（Trae CN国内版）
➢ 辅助工具：Git（版本控制）、Postman（接口调试）、maven/pip
（包管理）

### 1.2后端学习

- ①.使用 Python 的 FastAPI 框架实现了一个**BMI（身体质量指数）计算器**的完整 Web 应用。将前端页面和后端 API 接口整合在了一个文件
    
    !image.png
    
    - 项目说明
        
        这段代码使用 Python 的 FastAPI 框架实现了一个**BMI（身体质量指数）计算器**的完整 Web 应用。它将前端页面和后端 API 接口整合在了一个文件中。
        
        具体来说，代码主要完成了以下四个核心功能：
        
        ### 1. 核心计算逻辑 (`get_bmi_level`)
        
        定义了一个函数，用于根据传入的 BMI 数值判断体重等级。它采用了中国标准的 BMI 划分界限：
        
        - `< 18.5`：偏瘦
        - `18.5 - 24`：正常
        - `24 - 28`：超重
        - `≥ 28`：肥胖
        
        ### 2. 前端展示页面 (`GET /`)
        
        提供了一个根路由，直接返回一段包含 HTML、CSS 和 JavaScript 的字符串，渲染出一个美观的 BMI 计算器网页。
        
        - **UI 设计**：使用了渐变背景、圆角卡片和阴影，界面简洁现代。
        - **用户交互**：包含身高（米）和体重（公斤）两个输入框，以及一个计算按钮。
        - **异步请求**：通过 JavaScript 的 `fetch` API，将用户输入的数据发送给后端的 `/api/bmi` 接口，并在页面上动态展示计算结果（包括具体的 BMI 数值和对应的颜色提示）。
        
        ### 3. 后端 API 接口 (`GET /api/bmi`)
        
        提供了一个 RESTful 风格的 GET 接口，接收 `height` 和 `weight` 两个浮点数参数。
        
        - 接收参数后，利用公式 `体重 / (身高²)` 计算 BMI。
        - 将结果保留两位小数，并调用前面的判断函数得出体重等级。
        - 最终以 JSON 格式（如 `{"bmi": 21.22, "level": "正常"}`）返回给前端。
        
        ### 4. 启动服务
        
        在代码底部，使用 `uvicorn` 作为 ASGI 服务器，将应用运行在本地 `127.0.0.1` 的 `8000` 端口上。
        
        **总结来说**，这段代码实现了一个前后端分离逻辑（但在同一文件中）的 BMI 计算工具：用户在前端网页输入身高体重，前端通过 Ajax 请求后端 API，后端计算后将结果返回，前端再根据结果渲染出带有颜色提示的体重等级。
        
- ②.基于 **FastAPI** 框架开发的 **中医智能辨证诊断 API**。利用 **DeepSeek** 的大语言模型（兼容 OpenAI 协议），接收患者的症状和舌象信息，自动进行中医辨证分析，并返回证型诊断和中药处方建议。
    
    !image.png
    
    - 项目说明
        
        这份代码是一个基于 **FastAPI** 框架开发的 **中医智能辨证诊断 API**。它利用 **DeepSeek** 的大语言模型（兼容 OpenAI 协议），接收患者的症状和舌象信息，自动进行中医辨证分析，并返回证型诊断和中药处方建议。
        
        这是一个非常典型的 **“AI + 传统行业”** 的后端服务脚手架，结构清晰、健壮性好，且没有第三方库依赖（除了 FastAPI 生态）。
        
        以下我为你详细拆解这份代码的架构与亮点：
        
        ### **1. 核心功能概览**
        
        这个程序启动后会提供一个 Web 服务，主要功能是：
        
        - **输入**：接收 JSON 格式的症状列表（如 `["失眠", "口干"]`）和舌象描述（如 `"舌红苔黄"`）。
        - **处理**：将信息拼接成提示词（Prompt），发送给 DeepSeek 大模型。
        - **输出**：解析 AI 返回的 JSON 结果，提取“辨证结果”和“用药建议”返回给前端。
        
        ### **2. 代码架构详解**
        
        代码结构非常规范，遵循了 Python 的最佳实践，主要分为以下几个模块：
        
        ### **🛠️ 环境配置与加载 (`_load_dotenv`)**
        
        - **智能加载**：代码内置了一个 `_load_dotenv` 函数，优先尝试使用 `python-dotenv` 库加载 `.env` 文件，如果没有安装该库，则使用内置的手动解析逻辑，**实现了零额外依赖**。
        - **安全机制**：API 密钥通过环境变量 `DEEPSEEK_API_KEY` 读取，绝不硬编码在代码中，保证了安全性。
        
        ### **🤖 AI 对话核心 (`_call_ai` & `_parse_json`)**
        
        - **兼容调用**：利用 `openai` Python 库，通过设置 `base_url` 为 `https://api.deepseek.com` 来调用 DeepSeek 的服务。
        - **智能解析**：这是代码的一大亮点。考虑到大模型有时会“不听话”，返回带 Markdown 格式（如 `json ...` ）或额外解释的文本，代码设计了三层降级解析策略：
            1. 直接 JSON 解析。
            2. 剥离 Markdown 代码块标记后解析。
            3. 在杂乱文本中定位 `{` 和 `}` 符号截取 JSON。
        - **容错兜底**：如果解析失败或字段缺失，会返回默认的错误提示，防止服务崩溃。
        
        ### **🌐 API 接口定义 (`@app.post`)**
        
        - **路径**：`POST /tcm_diagnosis`
        - **校验**：对接收的数据进行了严格的非空校验（症状、舌象）。
        - **交互**：使用 Pydantic 模型 (`TCMRequest`, `TCMResponse`) 定义请求和响应格式，自动生成 OpenAPI 文档。
        
        ### **3. 关键参数配置**
        
        **表格**
        
        | **配置项** | **值/说明** | **备注** |
        | --- | --- | --- |
        | **模型名称** | `deepseek-chat` | DeepSeek 的主力对话模型 |
        | **系统提示词** | 设定为“资深中医专家” | 严格限制输出格式为纯 JSON |
        | **温度 (Temp)** | `0.7` | 保持一定的创造性，同时保证准确性 |
        | **最大 Token** | `1024` | 足够生成一段详细的诊断和处方 |

        `export DEEPSEEK_API_KEY="sk-你的密钥在这里"`

        **env**

        ### **5. 潜在优化建议**
        
        虽然代码已经很完善，但如果用于生产环境，还可以考虑以下几点：
        
        - **模型微调**：目前直接使用通用的 `deepseek-chat`，如果对中医古籍进行过微调（Fine-tuning），辨证的准确率会大幅提升。
        - **流式输出**：目前是等待 AI 生成全部内容后一次性返回，可以增加 `stream=True` 实现逐字输出，提升用户体验。
        - **缓存机制**：对于相同的症状组合，可以缓存结果，减少 API 调用成本。
        
        这是一份质量很高的工程化代码，逻辑严密，非常适合用来构建中医辅助诊疗系统。
