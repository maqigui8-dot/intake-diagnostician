# 01_cover

这一版主要汇报中医诊前问诊系统今天完成的改造。对比基准是今天修改前的原版本，以及今天全部修改完成后的新版本。核心变化可以概括成一句话：补充问诊从单张问题卡，升级成了对话式、可追踪并且一定能够结束的问诊闭环。后面我会先对比改造前后，再说明现在的完整流程，最后汇报测试和验证结果。

# 02_before_after

今天的修改不是只改了一个页面，而是覆盖了五个层面。交互上，从单张问题卡改成保留历史的聊天；显示上，把完整度、缺失必问项和建议选问项留在系统内部；数据上，追问新增稳定 key 和必问、选问类型；收敛上，同一缺口不能换一种说法重复问，选问项也不能一直拖住流程；边界上，正常轮数仍由信息决定，同时增加后台十二轮安全保护。对应地，前端、后端、两个 Skill、智能分析协议和测试都做了同步修改。

# 03_conversational_followup

这一页重点展示交互变化。原来用户主要看到当前的一张问题卡，前后回答不容易连起来理解。现在补充问诊进入独立聊天区，历史问题和回答会持续显示，当前问题接在对话后面，每轮只问一个信息点。患者只需要像聊天一样按实际情况回答，不会看到系统内部的缺失必问项、建议选问项或完整度字段。这样既保留了问诊上下文，也避免把内部判断直接暴露给用户。

# 04_current_flow

现在的完整流程从基础十题开始。提交基础资料后，系统先调用完整度判断，区分关键必问项和建议选问项。如果仍缺关键必问项，就生成一个自然问题和稳定 key，用户在聊天区回答，系统保存问题、回答、key 和类型，然后重新做完整度判断。这个过程可以按信息需要继续超过五轮，但不是无限循环。当信息足够、只剩选问项、模型重复同一个缺口，或者达到后台安全边界时，就进入结果页，生成诊前档案和推荐检查项目，最后保存记录。

# 05_skills_and_convergence

两个 Skill 的职责现在分得比较清楚。第一个 tcm-intake-checklist 负责决定问什么，它按照十问歌、当前主诉和问诊经验判断资料是否够用，并区分关键必问项和建议选问项。第二个 tcm-questioning-guide 负责决定怎么问，把最重要的缺口转成自然、温和而且一次只有一个问点的问题。智能分析同时返回问题、稳定 key 和类型。模型输出以后还要经过策略层：只有关键必问项可以继续，选问项不能阻止结束，已经问过的 key 不得重复，达到十二轮时后台安全结束。

# 06_validation

最后是实际验证结果。系统允许正常超过原来的五轮，第十二个回答可以保存；第十三次提交会被后端拒绝，因此不会再出现三十轮仍不结束。后端三十一项测试全部通过，覆盖策略、接口和 Skill 分析；前端十五项测试全部通过，覆盖页面阶段和患者可见内容。生产构建也已经通过，页面没有控制台错误。所以这一轮修复不是依靠模型自己决定停下来，而是在产品交互、数据结构和流程策略三个层面共同保证追问既能继续，也一定能够结束。
