# 项目汇报 PPT 视觉重做设计

## 目标

在不改变已确认的 14 页内容结构和汇报重点的前提下，重新设计整套 PPT。新版应适合课题组组会汇报，延续旧版“暑期学习进展汇报”的配色与克制感，同时解决上一版过于平、密、像说明文档的问题。

## 视觉方向

- 类型：学术汇报型。
- 背景：暖米白 `#F7F5EF`。
- 主色：墨绿 `#155348`。
- 强调色：陶土橙 `#C86A3A`。
- 正文：灰绿色 `#566762`。
- 结构线：浅灰绿 `#BFCFC9`。
- 字体：微软雅黑。
- 风格：平面、无阴影、无渐变、少圆角、少图标。
- 标题：封面居中；其余页面统一位于左上角。

## 版式原则

1. 每页只建立一个主要视觉中心，避免把所有内容平均分散。
2. 页面使用大标题、重点数字、短解释和结构图组合，不再使用大面积横向文字表格。
3. 正文保持足够内容供现场讲解，但页面只保留支持讲述的关键词和结论。
4. 墨绿色承担结构，陶土橙只标记关键决策、风险和流程转折。
5. 同一套 PPT 中交替使用留白页、左右分栏页、中心机制图和操作展示页，避免页面重复。

## 页面设计

### P01 封面

保持旧版居中大标题和橙色短线。删除多余说明，只保留项目名称、汇报人和日期。

### P02 项目背景与问题

左侧用一句较大的问题概括建立视觉中心，右侧用四条短问题围绕一条纵向基线展开。底部用一行总结项目需求。

### P03 项目目标与定位

以“诊前资料整理”为中心，四个目标围绕中心排布。下方独立放置能力边界，突出系统不承担诊断职责。

### P04 系统整体架构

重画为从上到下的四层架构图。交互层、接口层、决策层、数据层宽度一致；决策层用陶土橙突出“Agent 理解 + 规则决策”的分工。

### P05 系统角色与主要功能

患者端与医生端不再做对称文字清单。改为左右两个角色区域，中间用数据流连接，底部单独说明 patient_id 隔离和医生端只读原则。

### P06 完整问诊流程

采用弯折式七步路径，让流程占据页面主体。把“每次回答后重新判断”画成反馈回路，避免普通直线时间轴。

### P07 结构化字段与信息来源

左侧显示五类字段构成，右侧显示问题来源链路：字段定义、Agent 证据、状态更新、规则选择。突出“问题目标来自字段配置”。

### P08 资料完整度如何判断

以中央完整度判断器为核心。左侧输入五种字段状态，右侧输出完整、继续追问或保护性结束。底部强调“完整不等于所有字段填满”。

### P09 追问优先级与决策机制

使用五级递进阶梯，危险信号位于最高优先级。右下角保留一个真实选择例子，说明规则选字段、Agent 组织问题。

### P10 何时停止追问

使用清晰的判断树。中央判断节点向“继续追问”“正常结束”“保护性结束”三条路径分流，分别标出触发条件。

### P11 项目实现中的关键难点

使用四条横向问题线。每条依次呈现“难点、解决方式、实现状态”，但减少表格感；“已实现”作为右侧轻量状态标记。底部保留当前边界。

### P12 身份选择与患者端展示

采用一张主截图和两张局部截图的杂志式布局。截图框使用实线细边和编号，不使用大面积虚线框。

### P13 问诊过程展示

三张截图采用不同宽度，形成从开放描述到追问再到档案的视觉推进。用底部流程线连接，不使用大箭头。

### P14 医生工作台与总结

医生工作台截图占据主要面积。截图下方用三个短注释指向患者列表、问诊详情和决策解释。右下角以一句项目总结收束，不设置普通“谢谢”结束页。

## 内容边界

- 保留现有 14 页顺序与标题。
- 不新增后续计划页。
- 不新增 SQLite、三次复诊测试或 Spring Boot 内容。
- P12 至 P14 继续保留截图位置，由用户后续替换。
- 重点仍为完整度判断、追问来源、下一问选择、停止条件和实现难点。

## 交付与验证

- 使用 PPT Master 逐页生成 SVG，并导出 PPTX。
- 同时提供高兼容版，避免旧版 PowerPoint 或 WPS 无法打开。
- 检查 14 页数量、演讲备注、颜色字体锁定和文件结构。
- 对机制图页面和操作展示页面进行视觉渲染检查。
