# 对话式追问收敛设计

## 目标

追问轮数由信息完整度动态决定，不再固定为 5 轮；同时避免模型反复换一种说法追问，确保流程能够稳定结束。

## 结束规则

1. 只有尚未覆盖的关键必问项可以继续阻塞流程。
2. 建议选问项可以保留在内部分析中，但不能触发下一轮追问。
3. 每个追问缺口必须有稳定的 `follow_up_key`。已经询问过的 key 不得再次询问，即使患者回答“不知道”也视为已经尝试获取。
4. 正常情况下由完整度判断动态结束；后台设置 12 轮安全兜底，达到后不再展示下一题。这个数字不在患者界面显示。

## 数据流

- 智能分析输出当前问题、稳定缺口 key 和问题类型。
- 提交回答时一并保存 key 和类型。
- 后端策略层统一检查选问项、重复 key 和安全轮数。
- 前端保留同样的 12 轮防御性判断，避免异常响应继续显示问题。

## 用户体验

- 页面仍显示“第 N 问”，不显示总轮数。
- 缺失必问项和建议选问项继续作为内部判断，不向患者展示。
- 达到兜底或模型重复时直接进入信息整理结果，不弹出技术错误。

## 验证

- 第 6 轮仍可继续。
- 第 12 个回答提交后结束。
- 同一缺口换问法也不能重复。
- 只有选问项缺失时不继续追问。
- 前后端测试、构建和浏览器流程均通过。
