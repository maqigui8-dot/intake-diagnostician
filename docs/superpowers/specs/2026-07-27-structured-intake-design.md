# 结构化问诊改版设计

## 目标

把现在的“AI 老中医”项目，从偏自由聊天的问诊方式，升级成参考图那种更清晰的“结构化问诊流程”。

新的版本要做到：

- 用户不用一直自己组织语言，也能一步步完成问诊。
- 页面能清楚显示当前问到第几题、还剩哪些问题、已经收集了哪些信息。
- 仍然保留 AI 老中医的温和解释和灵活追问，不变成冷冰冰的表单。
- 最后能生成并保存“四诊档案”。

## 推荐方案

采用“混合模式”：

- 主流程用固定问题推进，保证问诊稳定、完整。
- 每一题提供几个选项，用户点选即可。
- 每一题也提供一个补充输入框，用户可以写自己的情况。
- 后端保存结构化答案，比如主诉、持续时间、寒热、出汗、饮食、睡眠等。
- AI 负责补充一句简短解释、必要时生成追问、最后整理四诊档案。

这样既像参考图一样清楚，又不会失去你原来项目里的 AI 感。

## 前端设计

页面改成三栏布局。

左侧是问诊流程：

- 显示项目名称：AI 老中医 / 中医诊前助手。
- 显示四个阶段：导诊、预问诊、信息确认、检查建议。
- 当前阶段用浅绿色高亮。
- 已完成阶段显示完成状态。
- 底部放一个隐私说明卡片，让页面更像医疗问诊产品。

中间是当前问题：

- 顶部放一个欢迎卡片，有“小郎中”头像、问候语、简短说明。
- 主体显示当前题目，比如“问题 3 / 10”。
- 显示题目名称、问题正文和一句提示说明。
- 下面放多个可点击选项。
- 选项之外再放一个“补充描述”输入框。
- 底部放“上一题”和“下一题”按钮。
- 全部完成后，中间区域显示最终的四诊档案。

右侧是信息面板：

- 显示问诊进度百分比。
- 显示必问题列表：已回答、当前问题、待回答。
- 显示已收集信息摘要，比如主要症状、持续时间、伴随症状、其他信息。
- 完成后显示保存状态，也可以显示查看档案的入口。

视觉风格参考图片：

- 白色背景和浅色卡片。
- 主色从现在的偏蓝紫，调整为更柔和的绿色。
- 阴影要轻，界面要干净。
- 保留中医气质，但减少过多 emoji 装饰。
- 整体感觉更像一个实用的医疗助手，而不是单纯聊天页面。

## 后端设计

在现有 Agent 旁边增加一层“结构化问诊流程”。

每个问题大概长这样：

```json
{
  "id": "stomach_bloating_timing",
  "topic": "chest_abdomen",
  "field": "bloating_timing",
  "stage": "pre_intake",
  "question": "您的胃胀一般在什么时间段比较明显？",
  "hint": "了解症状出现的时间有助于判断病因",
  "options": [
    { "id": "morning", "label": "早上起床后" },
    { "id": "afternoon", "label": "中午或下午" },
    { "id": "evening", "label": "晚上" },
    { "id": "all_day", "label": "全天都明显" },
    { "id": "unsure", "label": "不太确定" }
  ]
}
```

每个问诊会话需要保存：

- 会话 ID。
- 当前问到第几题。
- 每一题的结构化答案。
- 用户补充描述。
- 已收集信息摘要。
- 是否已经完成问诊。
- 最终生成的四诊档案 Markdown。

新增或调整接口：

- `GET /api/intake/session/{session_id}`：获取当前问诊状态、题目列表、进度和已收集摘要。
- `POST /api/intake/session/{session_id}/answer`：提交某一题的答案和补充描述。
- `POST /api/intake/session/{session_id}/complete`：生成最终四诊档案，并标记问诊完成。
- 保留 `/api/save_record` 和 `/api/records`，但保存时增加结构化答案。
- 暂时保留 `/api/chat`，方便旧版逻辑兼容。

现有 Deep Agent 的职责要收窄：

- 不再让 Agent 控制完整问诊顺序。
- Agent 可以在用户回答后生成一句温和解释。
- 当补充描述里出现缺失信息或风险信号时，Agent 可以给出一个额外追问。
- 最后由 Agent 根据结构化答案整理四诊档案。
- 检查建议要保守，不能替代医生诊断。

## 数据流程

1. 前端创建一个 `session_id`。
2. 前端请求当前问诊状态。
3. 后端返回当前题目、总进度、题目列表、已收集摘要。
4. 用户选择答案，也可以填写补充描述。
5. 前端提交答案。
6. 后端保存答案，更新进度和摘要，返回下一题状态。
7. 所有必问题完成后，前端请求生成最终档案。
8. 后端生成四诊档案，并保存记录。

## 第一版题目范围

第一版先做 10 个核心问题，基于现有的“十问歌”技能：

1. 主要症状。
2. 症状持续时间。
3. 寒热偏好。
4. 出汗情况。
5. 头身感受。
6. 大便和小便。
7. 食欲和消化。
8. 胸腹情况。
9. 睡眠情况。
10. 旧病、用药和可能诱因。

女性经期、儿童问诊、专病分支这些先不放进第一版。后面可以作为条件分支继续扩展。

## 异常处理

如果 AI 调用失败：

- 用户答案仍然要保存。
- 页面显示一条默认的温和提示。
- 用户仍然可以继续下一题。

如果最终档案保存失败：

- 已生成的四诊档案仍然留在页面上。
- 页面提供“重试保存”。

如果用户返回修改前面的答案：

- 重新计算进度和信息摘要。
- 已生成的最终档案作废，需要重新生成。

## 测试和验证

后端需要验证：

- 新会话能正常初始化。
- 提交答案后进度会变化。
- 返回上一题修改答案后，摘要能重新计算。
- AI 不可用时，最终档案能用兜底逻辑生成。
- 保存记录时包含结构化答案。

前端需要验证：

- 项目能正常构建。
- 桌面端显示三栏布局。
- 小屏幕下能变成可用的单栏布局。
- 选中答案、进度、右侧摘要能同步更新。
- 完成后能显示四诊档案表格。

手动检查：

- 从头完成一次完整问诊。
- 修改前面的答案，再重新完成。
- 模拟 AI 失败，确认流程不会卡住。
- 确认保存后的记录还能通过原来的记录接口读取。

## 第一版不做的内容

- 用户登录。
- 真实消息通知。
- 完整诊断功能。
- 开方或处方建议。
- 所有中医专科分支。
- 完整档案管理后台。

## 成功标准

- 打开页面后，看起来像一个引导式问诊产品，而不是单纯聊天窗口。
- 用户不打字也能完成问诊。
- 用户需要时也可以补充自然语言描述。
- 问诊进度、必问题、已收集信息能保持同步。
- 最终能生成并保存四诊档案。
- 原来基础接口尽量保持兼容，避免一次改动太大。
