# 患者个人问诊历史设计

## 目标

在患者端为当前演示患者“张女士”提供自己的已完成问诊档案列表，能够回看每次问诊的诊前档案、问答记录和检查准备事项。

## 范围与边界

- 患者端左侧新增“我的问诊记录”，每项展示日期、主要诉求和“资料已整理”状态。
- 点击记录只打开该患者自己的患者安全档案快照；不恢复为可继续填写的旧会话。
- 新建问诊仍创建同一患者的新会话。
- 患者端接口不返回医生端完整度、缺口、规则版本、置信度、执行度或医生摘要。
- 当前项目没有登录体系，因此使用固定演示患者标识 `demo-zhang`。这是演示隔离，不是生产级身份认证。
- 旧记录没有患者标识时不出现在患者端，避免意外暴露既有文件。

## 方案

后端在保存完成档案时写入 `patient_id`，并新增两个患者专用接口：列表接口按固定演示患者过滤；详情接口先校验归属，再映射为患者安全快照。映射逻辑放在独立的纯 Python 模块，便于单元测试和避免路由中混入展示规则。

前端在非医生模式加载该列表，保存成功后刷新。用户点击记录后进入只读详情视图，展示诊前档案、完整问答记录及检查建议；可返回当前问诊或开始一次新问诊。

## 错误处理与验证

- 无记录时展示空状态，不显示任何历史患者信息。
- 查询非本人记录返回 404，不泄露该记录是否属于其他患者。
- 后端测试验证归属过滤和医生字段剔除；前端测试验证侧栏入口、专用 API 和患者端不出现内部判断字段。
