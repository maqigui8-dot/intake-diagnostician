# 医生端决策解释栏易读性改造设计

## 目标

让老师或医生在不理解内部评分规则的情况下，快速看懂三个问题：诊前核心资料是否齐全、系统已经收集了哪些线索、还有哪些内容建议诊中补充。

## 当前问题

- “病因与风险 43.5%”“中医诊前 52.5%”把核心项和选填项共同计入分母，容易被理解成问诊只完成一半。
- 百分比实际表示扩展字段覆盖程度，不代表患病风险，也不直接决定是否结束追问。
- “16/16 已完成”和较低百分比同时出现，视觉上形成矛盾。

## 展示方案

### 1. 核心诊前资料

保留醒目的 `16 / 16`，标题改为“核心诊前资料已完成”。补充说明：核心必问项全部确认，已满足停止自动追问与保存档案的条件。

### 2. 已覆盖的主要线索

取消病因与风险、中医诊前的百分比和进度条。根据已确认字段，按类别显示简短摘要，例如：

- 病程与风险：病程、饮食变化、活动情况、既往疾病、近期检查。
- 中医诊前：食欲、二便、睡眠、疲乏等主要症状。
- 用药安全：过敏、当前用药、既往疾病、危险信号。

只展示实际已收集到的类别，不用百分数评价丰富程度。

### 3. 诊中建议补充

从未询问、部分明确或无法提供的扩展字段中生成中文列表，例如家族史、寒热出汗、浮肿困重、舌象。明确标注：“以下为选填资料，不影响诊前档案保存，由医生结合主诉按需确认。”

### 4. 安全提醒与检查建议

- 安全提醒继续单独突出显示。
- 存在胸痛等危险信号时，显示“请医生优先进行线下安全评估”，不显示容易误解的“暂无检查候选”。
- 没有危险信号时，再展示常规检查建议或“由医生诊中决定”。

## 数据与组件边界

- 后端现有 `field_groups`、`decision_explanation`、`safety_alerts` 和 `recommended_exams` 已包含所需数据，不改变问诊停止规则。
- 前端 `DecisionExplanationPanel.vue` 负责把字段状态转换为“已覆盖线索”和“诊中建议补充”。
- 不删除医生端其他详细字段；本次只重构右栏摘要表达。

## 异常与空状态

- 尚未选择问诊时：提示选择一条有效问诊记录。
- 无扩展缺口时：显示“当前无额外诊中补充项”。
- 无安全提醒时：显示“当前未记录危险信号”。
- 字段缺少中文标签时：使用所属资料类别，不直接展示英文键名。

## 验证要求

- 右栏不再出现病因与风险、中医诊前的覆盖百分比。
- 核心必问完成情况仍清晰可见。
- 已覆盖线索与诊中建议补充均来自真实字段状态。
- 危险信号优先于常规检查建议展示。
- 前端测试和生产构建通过。
