# DeepSeek 模型接入替换设计

## 目标

将当前后端的千问云端模型替换为 DeepSeek 云端模型，不改变现有问诊流程、两个 Skill、确定性执行度计分、追问策略和前端接口。

## 方案选择

采用 DeepSeek 的 OpenAI 兼容接口，继续复用现有 `ChatOpenAI` 客户端：

- 环境变量使用 `DEEPSEEK_API_KEY`。
- 接口地址使用 `https://api.deepseek.com`。
- 默认模型使用 `deepseek-v4-flash`，优先保障追问响应速度和调用成本。
- 未配置 DeepSeek 密钥时，继续使用本地 Ollama `qwen3:8b` 作为回退。
- 删除运行时对 `DASHSCOPE_API_KEY` 和千问云端地址的依赖。

## 配置与安全

密钥只保存在后端本地 `.env`，该文件已由项目忽略规则排除，不写入 Python、测试、文档或前端代码。README 仅展示占位符。

用户已经在聊天中发送过密钥。完成验证后，建议在 DeepSeek 控制台轮换密钥，降低聊天记录泄露带来的风险。

## 错误处理

DeepSeek 初始化或调用失败时，沿用现有智能分析超时和固定安全项回退逻辑，不让患者流程卡住。未配置云端密钥时使用本地 Ollama。

## 验证

- 单元测试验证 `DEEPSEEK_API_KEY` 存在时模型名、接口地址和密钥来源正确。
- 单元测试验证未配置密钥时仍选择 Ollama。
- 全量运行后端 65 项测试和前端 14 项测试。
- 启动后端后执行一次最小 DeepSeek 请求，确认密钥、模型和网络可用。
- 检查源码、测试和文档中没有真实密钥。

## 不在本次范围

- 不切换到推理型模型。
- 不改动信息完整度权重和停止阈值。
- 不改变患者页面与医生页面。
- 不移除本地 Ollama 回退。
