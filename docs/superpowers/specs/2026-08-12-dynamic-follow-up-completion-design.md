# 动态追问结束规则设计

## 目标

补充问诊不再固定限制为五轮。系统每收到一次患者回答后，重新依据十问歌、主诉特点和老中医问诊经验判断资料是否足以支持后续诊中判断和开方前准备。

## 结束规则

- 分析结果为 `needs_follow_up` 且返回了当前问题时，继续对话式追问。
- 分析结果为 `complete` 时结束追问，进入诊前档案和推荐检查项目页面。
- 分析未返回可用问题、出现危险信号或服务暂不可用时，进入对应的结束或重试状态。
- 追问次数只作为历史记录和“第 N 问”展示，不再参与完整度判断，也不作为保存档案的条件。

## 修改范围

### 前端

- 去掉“第 N / 5 问”和分析中的“0/5”等固定上限展示，只显示“第 N 问”或“正在整理回答”。
- 删除达到五轮后强制进入结果页、阻止提交和显示上限提示的逻辑。
- 最终结果仍只在分析确认信息足够或没有可用追问时显示。

### 后端

- 删除 `MAX_FOLLOW_UP_ANSWERS` 和提交回答时的五轮拦截。
- 状态继续返回 `follow_up_count`，不再返回 `max_follow_up_answers`。
- 分析提示词不再要求达到固定次数后停止。

### Skills

- `tcm-intake-checklist` 继续负责判断是否够用以及下一项最重要缺失信息。
- `tcm-questioning-guide` 删除“五轮上限”，保留每轮只问一个问题、不得重复追问和危险信号优先规则。

## 验收标准

- 第六次及之后的追问回答可以正常保存。
- 只要分析仍返回 `needs_follow_up` 和一个问题，前端就继续显示对话。
- 只有分析返回 `complete` 或没有可用问题时进入最终结果。
- 页面和 Skill 文本中不再出现固定五轮限制。
- 前端测试、后端测试和生产构建全部通过。
