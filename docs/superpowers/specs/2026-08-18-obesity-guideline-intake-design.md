# 成人肥胖指南驱动的诊前采集改造设计

## 1. 目标

将现有中医诊前问诊原型改造成面向成人肥胖诊疗的中西医结合诊前信息采集系统。系统负责采集、整理、计算和提示，不直接确诊、不输出患病概率、不自动辨证或开方，最终结果由医生确认。

## 2. 依据与边界

- 主要依据：《肥胖症诊疗指南（2024年版）》中的诊断标准、病因调查、体格检查、实验室检查和相关疾病评估。
- 中医信息继续参考十问歌和中医问诊经验，但定位为诊中辨证与开方前的补充资料。
- 系统仅面向成年人。未满18岁时停止使用成人规则并提示转入儿童青少年评估流程。
- 页面只提示“达到成人肥胖范围，待医生确认”，不向患者展示“已确诊”。

## 3. 信息分层

### 3.1 基础诊断层

以下字段是正常完成的硬性条件：

- 年龄
- 生理性别
- 身高（厘米）
- 当前体重（千克）
- 测量时间或数据新鲜度
- BMI（后端自动计算，不由AI生成）

腰围为强烈建议项，用于判断中心性肥胖；臀围和腰臀比为选问项。BMI分级、中心性肥胖标准和腰臀比判断全部由后端确定性规则计算。

### 3.2 病因与风险层

包括体重变化过程、儿童期肥胖史、变化诱因、既往减重经历、肥胖与相关疾病家族史、可能增重的疾病和药物、过敏与当前用药、肥胖相关疾病、近期检查、饮食、运动、睡眠、工作活动强度、吸烟、饮酒、暴食与精神心理情况。

相关检查拆分为血糖与糖化血红蛋白、血脂、尿酸、肝功能、肾功能、甲状腺功能。只记录是否检查、检查时间、结果是否异常和患者能够提供的数值，不由AI解释检查结果。

### 3.3 中医诊前层

包括寒热、汗出、食欲与口渴、二便、睡眠与情绪、疲劳与气短、身体困重与浮肿、胸腹不适和可选舌照。脉象留给医生诊中采集。

## 4. 采集流程

1. 患者先填写年龄、性别、身高、体重和腰围等结构化基础资料。
2. 后端计算BMI、肥胖程度和中心性肥胖提示。
3. 系统以开放问题了解主要诉求和体重变化。
4. 按病因与风险缺口进行对话式追问。
5. 按中医资料缺口进行对话式追问。
6. 达到完成条件后生成医生端诊前档案和检查候选项目。
7. 患者端只显示资料已整理和就医提示；医生端查看内部完整度、证据、矛盾与待确认项。

## 5. 完成条件

正常结束必须同时满足：

- 基础诊断硬性字段全部明确，并成功计算BMI。
- 安全硬性字段全部明确：危险信号、过敏史、当前用药、重要既往疾病。
- 病因与风险资料执行度达到80%。
- 中医诊前资料执行度达到70%。
- 不存在尚未处理的核心字段矛盾。

患者明确不清楚或不愿回答时，记录为“无法提供”，最多进行一次委婉确认，之后交给医生诊中核实。不得仅依赖总分越过基础诊断硬性字段。

## 6. 对话与澄清处理

- 一次只问一个主要信息点。
- “这是什么”“什么意思”“没听懂”等属于澄清请求，不作为医学证据，不增加完整度，也不消耗该字段的追问次数。
- 收到澄清请求后，先用日常语言解释当前概念，再重新询问同一字段。
- 患者一次回答包含多个有效信息时，可以同时更新多个字段，但证据必须能在患者原话中找到。
- AI不可用时使用后端固定问题继续采集全部字段，不能只完成安全项后提前生成档案。

## 7. 两个Skill职责

### 7.1 tcm-intake-checklist

负责字段注册、必问项与选问项判断、条件字段启用、优先级、完整度缺口和停止条件。AI不能修改硬性字段、权重或阈值。

### 7.2 tcm-questioning-guide

负责把指定字段转换成自然、温和的患者问题，处理澄清、拒答和前后矛盾。不得向患者暴露内部字段名、分数、缺失项、诊断或处方结论。

## 8. 医生端结构

医生端按以下区块展示：

1. 基础测量与肥胖范围：年龄、性别、身高、体重、BMI、腰围及规则提示。
2. 肥胖病程与可能病因：起病时间、变化速度、诱因、药物、疾病和家族史。
3. 相关疾病风险：血压、代谢检查、睡眠呼吸暂停、心血管和生殖相关风险。
4. 生活方式与心理情况：饮食、运动、睡眠、工作、烟酒、暴食和情绪。
5. 中医诊前资料：十问相关症状和舌象。
6. 待医生确认：缺失、无法提供、矛盾、安全提醒和检查候选。

## 9. 检查建议边界

检查模块只生成“供医生评估的检查候选”，每项包含触发依据、适用条件和规则版本。不得因为肥胖范围成立就固定推荐全部检查，不得输出价格，不得替代医生开具检查。

## 10. 测试与验收

- 年龄、性别、身高或体重缺失时不能正常完成。
- BMI由后端正确计算并按成人标准分级。
- 男女性腰围标准分别生效。
- “这是什么”不会污染字段、增加分数或消耗追问次数。
- AI不可用时仍能使用固定问题完成全流程。
- 危险信号持续提示但不清除既有资料。
- 患者端不出现内部完整度和诊断结论。
- 医生端能够看到证据、冲突、无法提供项和规则版本。
- 建立完整、缺失、矛盾、拒答、未成年人、特殊人群和模型不可用等测试病例。
