# 01 封面

各位老师好，我汇报的项目是“中医诊前信息采集与整理系统”。这个项目关注的不是自动诊断，而是患者见到医生之前，如何把零散的自然描述整理成医生能够快速查看的结构化资料。

# 02 项目背景与问题

患者通常按自己的感受表达，信息自然但比较零散。医生需要反复确认病程、生活方式和安全信息。普通聊天式问诊还容易不停追问，而且医生不知道系统为什么问、为什么停。因此项目聚焦四个要求：结构化采集、有限追问、及时停止和过程可解释。

# 03 项目目标与定位

项目的目标是把患者自然语言整理为结构化资料，根据缺口选择下一问，并用核心完整度决定停止时机。系统只辅助资料整理，不自动诊断、不输出患病概率、不自动开方，也不能替代医生面诊。

# 04 系统整体架构

系统分为四层。Vue 3 提供患者端和医生端；FastAPI 提供接口；决策层由 Agent 和规则系统协作；MySQL 保存完整业务数据。这里最重要的分工是：大模型负责理解和表达，确定性规则负责优先级、完整度和停止边界。

# 05 系统角色与主要功能

患者端负责提供信息，医生端负责查看和理解信息。每个会话与档案都绑定 patient_id，避免不同患者的数据混在一起。医生端当前保持只读，不能改变患者原始回答。

# 06 完整问诊流程

患者先选择身份并填写基础资料，然后进行开放描述。Agent 抽取信息后，系统更新字段状态、重新计算完整度，再决定继续追问还是生成档案。这个判断在每次回答后都会发生，所以问诊不是固定轮数。

# 07 结构化字段与信息来源

系统将信息分为基础测量、病程、中医症状、生活方式和安全信息。每个字段都有标准问题、优先级、核心属性、尝试次数和适用条件。Agent 提取字段值和原文证据，规则判断是否确认，因此每个问题都有明确来源。

# 08 资料完整度如何判断

完整度不是简单统计填了多少字段。系统区分尚未询问、部分获取、已确认、无法提供和不适用。真正阻塞结束的是核心字段、安全缺口和未解决冲突；可选字段不会无限阻塞。

# 09 追问优先级与决策机制

下一问按照五级优先序选择：危险信号、核心缺口、冲突字段、高优先级普通字段、可选信息。规则先选目标字段，Agent 再把它表达成自然问题。已确认、不适用或达到尝试上限的字段不再重复询问。

# 10 何时停止追问

系统不依赖固定轮数。核心信息满足且没有安全缺口、没有冲突时正常结束；多次无法回答、问题重复或剩余信息不适合在线采集时保护性结束。保护性结束只表示停止继续询问，不代表资料完整。

# 11 项目实现中的关键难点

四项主要难点都已经在当前版本实现：核心字段驱动停止、规则约束 Agent、尝试次数防止重复，以及 patient_id 数据隔离。仍需说明边界：演示身份不是正式鉴权，真实临床效果和规则覆盖范围还需要进一步验证。

# 14 项目操作展示：医生工作台与总结

医生工作台分为患者列表、问诊详情和决策解释三部分。医生不仅能看结果，也能看到关键缺口、问题来源和停止原因。项目最终实现的是用规则约束 Agent，形成安全、可追踪、可解释的诊前资料整理流程。
